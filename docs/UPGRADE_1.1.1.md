# 从 1.0.x / 1.1.0 升级到 1.1.1

保留原目录、Compose 项目名、`.env`、数据卷或 `data` 目录。不要删除卷，也不要执行 `docker compose down -v`。更换目录名称可能使 Compose 创建新的空卷，看起来像丢失旧数据。

1. 等待研究结束或停止任务，按原部署文档备份数据库和 `secret.key`。Docker 数据在原有 named volume，Python 运行的数据在原 `LEXCITE_DATA` / `data`。
2. 把此版项目文件整体更新到原项目目录，包括 `app`、`static`、依赖清单、脚本、文档和 Dockerfile；保留 `.env` 与所有业务数据。不应只换一个 JS 文件。
3. Docker 运行 `docker compose up -d --build`；若原本使用 Ollama 组合文件，继续使用相同的两个 `-f` 文件。Python 部署停止服务、安装当前 requirements，再使用原参数启动 `app.main:app`。保持一个 worker。
4. 启动自动为 `research_jobs` 增加 `reasoning` 字段；更早版本会先创建该表。已导入法规、案件、密码、已确认事实和旧引用快照保留，无须重新初始化。旧模型配置保留，新增设置采用默认值。
5. 刷新网页，左下角应显示 1.1.1；页面/脚本/后端版本不一致会提示完整更新。API `/healthz` 也应返回 1.1.1。
6. 到“模型与设置”核对思考模式和预算。旧版 DeepSeek 账户配置不会被自动覆盖；若仍是旧模型 ID，请按平台当前列表更新。点击保存、测试，再用练习案件检验完整 Agent 流程。
7. 如需联网，另行配置博查密钥或已有 SearXNG；模型 API Key 不具备搜索权限。教程中的“国产模型 API”现提供三家标签页，Ollama 章节继续保留。

验收：提交问题时看到真实步骤；错误引文应触发修正；结果引用能打开完整条文；刷新能恢复运行进度。新抓到的官网法规必须复核启用后才作为法源。

## 本版新增验收

在同一案件先问原问题，再补充事实，最后问“之前不是告诉你了吗”。展开“本轮采用的用户信息”，确认事实仍在，已提供的事项不再反复列为问题，“未知”仍为未知。

在“模型与设置”保留“输出格式：自动兼容”，勾选“展示并保存模型返回的思考内容”。保存、测试连接；使用支持思考字段的模型实际研究，在“模型思考”页签检查接口内容，刷新后仍可查看。接口没有返回时应明确提示。旧版回答没有保存此字段，不能补回历史思考。

若出现 HTTP 400，新版显示供应商错误代码/描述。针对不支持 `response_format` 的端点可改“提示词 JSON”；检查思考参数、模型权限与输出长度后重试。不要删法库解决模型参数错误。
