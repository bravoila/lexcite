# 研究 Agent、模型思考和联网（1.2.0）

## 这次改变了什么

1.0.x 已调用模型拆解、生成、复核，但没有根据失败反馈修正的循环。1.1 的有界 Agent 每轮制定计划、执行本地检索、生成分析，再由确定性引用校验与模型支持性复核决定是否重试。模型可改写查询或提出补充事实的问题，服务器固定工具范围。1.2.0 在此基础上新增事实整理、法源覆盖与官方补查，默认最多三轮、合计最多18次聊天调用；成功可提前结束。思考模式独立配置，Agent 不依赖供应商的 function calling 协议。

LLM 根据事实、适用条件、例外生成条件性分析；不是只检索原文。必须使用资料库中已经人工复核、日期和地区匹配的完整法条。每轮使用相同验证标准，不会因为多次失败而放宽规则。第三轮仍不合格时只展示通过部分、所缺材料或原文。

## 启用步骤

1. 升级整个项目，保留数据和 `.env`，重启；网页版本应为 1.2.0。
2. “模型与设置”填写 Ollama 或国产 API，先保存、后测试。模型思考可选默认/开启/关闭；默认不会发送强制抑制思考的参数或 `/no_think`。
3. 先采用 3 轮、360 秒总时限，按实际模型速度调整；思考模式可能需要更长单次超时和更高输出上限。它不能保证更准确。
4. 提问时选择“研究 Agent · 分析与引用校验”。进度显示阶段、轮次、耗时、检索结果数和校验通过数，“模型思考”页签单独显示接口实际返回的内容并标明未校验，最终结论仍需完整校验。
5. 需要时停止任务；当前 HTTP 调用可能仍由供应商处理和计费。页面刷新或关闭不停止任务；服务器重启会将任务标为中断，不自动重发付费请求。

## 联网配置

| 服务 | 服务地址 | 密钥 | 额外准备 |
|---|---|---|---|
| 博查 | `https://api.bochaai.com/v1` | 博查搜索 API Key | 开通搜索账户和可用额度 |
| SearXNG | 你自建服务的根地址，如 `http://searxng:8080` | 留空 | `search.formats` 启用 JSON；部署服务并保证法据可达 |

配置入口在“模型与设置 → 联网搜索”；保存后测试。1.2.0 在提问框增加“本次法源范围”：仅本地 / 联网补齐 / 沿用设置。默认不联网，管理员可改变默认值。

联网补查先使用官方 URL 目录，目录外文件再通过搜索服务查找。自动搜索只发送通过格式检查的法规名称，手工公开词单独发送；请勿在公开词中写案件隐私。完整正文通过元信息和条号检查后才进入本次临时证据，标为未人工复核，不自动写入法库。搜索摘要仍不可作为法条。

自动补查最多 2 次搜索 / 4 次官网读取；手工检索另限 1 次搜索 / 2 次读取。每个工具受时限约束。完整机制与局限见 [核心流程](CORE_RESEARCH.md)。

## API 与持久化

- `POST /api/cases/{cid}/research`：提交 `text`、`mode`、可选 `online_research`（null沿用设置）、`web_query`、`request_id`，返回 202 和任务。相同案件与 request_id 在输入相同的情况下返回已有任务；不能用同一 ID 提交不同内容。
- `GET /api/research`：当前运行任务；`GET /api/research/{id}`：任务状态、事件和完成结果。
- `POST /api/research/{id}/cancel`：请求停止，状态经过 `cancel_requested` 到 `cancelled`。
- `/api/search/settings`：GET/POST 读取公开设置或保存配置；`POST /api/search/test` 测试已保存配置。
- 旧 `/api/cases/{cid}/ask` 保留同步接口并使用同一 Agent 引擎。网页已改用任务 API。

所有接口沿用登录和变更请求校验。SQLite 新增 `research_jobs`，不替换旧表。消息对和任务完成状态原子提交；案件删除级联删除任务记录，运行时先停止任务。任务输入和过程也属于案件数据，备份需要妥善保存。

只支持单进程、单 worker；一个工作空间同时执行一个研究/索引任务。模型连接测试和搜索连接测试属于独立短任务。研究预算在工具边界和流式事件检查；网络等待、DNS、本地计算可能造成少量超时。没有供应商侧取消接口、分布式队列或跨机构权限体系。

## 思考模式适配与依据

核查日期：2026-09-25。模型具体支持程度以账户当前模型为准，以下为协议适配，不等于真实模型效果评测。

| 服务 | 开启/关闭参数 | 处理 |
|---|---|---|
| DeepSeek | `thinking: {type: enabled/disabled}` | 分开收集 content 与 reasoning_content |
| 阿里百炼、硅基流动 | `enable_thinking: true/false` | 百炼默认/开启模式使用 SSE；开启展示时其他服务也请求 SSE |
| Ollama、自定义兼容服务 | `reasoning_effort: high/none` | 兼容性依赖服务与模型；不支持时选默认 |
| 全部服务的默认模式 | 不发送思考控制参数 | 遵循服务默认，仍要求结构化最终答案 |

- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)
- [百炼结构化输出与思考模式限制](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output)
- [硅基流动 Chat Completions](https://docs.siliconflow.cn/docs/api/chat-completions-post)
- [Ollama OpenAI 兼容接口](https://docs.ollama.com/api/openai-compatibility)
- [博查官方接口示例](https://open.bochaai.com/)
- [SearXNG Search API](https://docs.searxng.org/dev/search_api.html)

“展示并保存模型返回的思考内容”默认开启，读取 `reasoning_content` / `reasoning`；也支持本地模型最终内容开头的 `<think>` 区块（该区块要完整收到才显示）。只展示接口实际提供的内容，无法获知未由接口提供的内部计算，未返回时明确提示。思考与答案分开保存，绝不作为事实或法源送入下一轮提示；最终结论仍受相同引用校验约束。

每次调用最多保存 24,000 字符，每次研究总计最多 100,000 字符，达到上限会标明截断。任务 `reasoning` 字段按流式片段节流更新，页面约 700ms 轮询；重载后可恢复，完成后写入回答历史。关闭展示停止收集后续内容，不会清空已有记录或强制关闭供应商思考。模型自身是否思考由另一个模式开关决定。

JSON 输出模式：`auto` 在百炼默认/开启思考时省略强制 `response_format`，其他情形请求 JSON object；`strict` 强制接口 JSON；`prompt` 仅使用 JSON 提示词。三个模式均运行本地 Pydantic 和引用校验。HTTP 400 的真实原因以脱敏后的供应商代码/描述为准，不自动归因于缺少法条；400/401/402/403/404/422 会停止相同参数重试。没有已通过结论时显示“模型调用失败”。

原始思考可能包含推测、错引或案件信息，界面单独标明未校验，不渲染 HTML。Markdown 法律研究导出默认不包含思考内容；它在本案网页历史和部署数据备份中保留。

## 对话事实与追问去重

每轮从本案用户原话、可回溯语义快照和手工确认事实重建上下文，不使用助手历史回答或思考作为事实。用户陈述摘要最多70项、18,000字符，另外召回最多12条完整用户消息、8,000字符；省略摘要段数会提示。对简短补充或“之前不是告诉你了吗”保留原研究主题，避免单独用提醒语检索。

先按规范化原话过滤重复追问，再最多增加一次模型核对，要求引用实际存在的用户来源片段。未知与已回答分开，矛盾保留待核对。此处理改善已知场景，不保证任意改写、隐含时间和主体的复杂陈述都正确识别。界面给出本轮使用信息快照，重要事实可手工确认。
