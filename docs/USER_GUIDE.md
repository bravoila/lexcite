# 法据使用说明

适用对象：使用浏览器的律师、法官和法律研究人员。部署完成后，下面的操作都可在网页内完成。

## 第一次打开

输入管理员提供的工作空间密码。首次初始化时，管理员会提供一次性初始化码，使用它设置自己的密码。

左侧有三个入口：

- **案件研究**：提问、继续讨论、查看引用与案件记忆。
- **法条资料库**：查看或导入法规，并复核来源和有效期。
- **模型与设置**：由管理员填写本地模型或云端API设置。

## 建立一份案件研究

点击“新建研究案件”，填写：

1. 案件名称：便于自己识别，例如“某公司买卖合同纠纷”。
2. 法律研究基准日期：本次研究需要查看哪个日期有效的法律。不能把今天默认等同于案涉行为时的适用日期。
3. 适用地区：例如“全国”或“上海市”。地区名称须与资料库记录一致；当前没有自动把某市映射到其省级法规。

“案件信息”可修改这些字段，修改只影响新回答。历史研究记录保留原来的日期和引用。

## 保存案件事实

在“已确认事实”点击“添加确认事实”，写入已核实的信息，例如合同约定、行为日期、已收到的款项。

系统会在当前案件后续研究中使用这些事实。发现错误可“移除此事实”。不同案件不会自动混用事实。对话记录会保存，但模型不会自动把自己的说法记成事实。

## 提问与看答案

建议提供主体、行为、时间、地区、合同约定以及具体要解决的问题。可以继续追问；关键长期事实应保存到“已确认事实”。

两种方式：

| 方式 | 用途 |
|---|---|
| 研究 Agent | 最多三轮计划、检索、分析、引用校验与证据复核，失败后自动修正，展示通过的结论 |
| 仅查法条 | 只列出相关原文，不进行法律适用分析；不需要模型 |

答案状态：

- **已核对引用**：引文匹配通过且模型复核通过，仍需自行审查适用条件和例外。
- **部分结论**：只显示有依据的部分，其余需要补充事实或法源。
- **仅供原文核对**：当前只展示检索结果，没有生成经验证的结论。
- **依据不足**：未找到符合版本、地区、复核要求的法源。

点击结论旁`[1]`等编号，或下面的法条卡片，可查看：引用片段、完整条文、版本、有效期和正文来源。有官网链接时可点击核对；没有链接时会显示文件名或“粘贴正文”，并标注“未提供官网链接”。**一定要阅读全文中的条件与例外。**“查看检索与校验过程”展示程序走了哪些步骤，不是完整的模型内部推理。

## 查看研究进度与联网线索

开始研究后，提问框上方显示当前阶段、轮次和真实步骤。遇到引用错误会显示需要修正的数量，然后进入下一轮。可以“停止研究”；当前请求结束或超时后生效。刷新页面可恢复查看，关闭浏览器不取消后台任务；重启服务器会中断尚未完成的任务，需重新提问。

在“模型与设置”可调整最多轮数（1—3）、总时限及模型思考模式。模型思考与 Agent 的循环分开控制；过程区可切换“模型思考”与“执行步骤”；思考只来自接口实际返回的字段，单独标明未校验。已提供的信息在右侧及回答快照中可查，“未知”会作为待调查信息保留。所有最终结论仍须引用核对。

在提问框“本次法源范围”开启“联网补齐官方法源”。内置目录文件直接读官网，目录外文件需在设置中配置博查或自建 SearXNG。留空公开检索词也可自动补查，手工词是额外可选项。完整官方原文通过检查后可作为本次临时证据，明确标注未人工复核；搜索摘要仍不能作为法条。

“官网线索 · 待复核”列出本轮查到的官网链接，并尝试读取前两页。点击“读取并导入复核”，程序会打开导入窗口，自动读取链接并预览；确认名称、版本、日期、正文后导入，再人工复核启用，重新提问即可使用。仅有搜索摘要或尚未复核的网页不能成为法律结论的依据。

完整逐步操作见 `LexCite_Step_by_Step_Guide.html`，包含阿里、DeepSeek、硅基流动标签页与 Ollama 配置。

## 添加法条

**文件和链接任选一种，不需要同时填写。** 法规名称、版本、地区和生效日期仍需要人工核对。

1. 进入“法条资料库” → “导入法规”。
2. 选择一种正文来源：
   - **上传文件 / 粘贴正文**：点击“选择文件”，上传TXT、MD、文字型PDF或DOCX；正文会自动填入下方。也可直接粘贴正文。官网链接可以留空；扫描件先用OCR转文字。
   - **读取官网链接**：粘贴官方原文网页或附件链接，点击“读取并预览”，或直接点击下方“读取链接并预览条文”。此时可以还未填写名称和日期，系统先自动读取正文并预览，无需上传文件；保存前再完整填写元信息。支持gov.cn、npc.gov.cn的HTTPS链接；请使用原文页，目录页或需要脚本加载的页面可能无法读取。
3. 核对名称、版本、地区、规范类型、生效日；知道失效日的，也应填写。这些信息不会交给模型猜测。
4. 点击“预览条文拆分”，检查条号、条数以及款、项、数字、否定词、例外和页尾是否正确。修改资料后要重新预览。
5. 点击“导入资料库”，对照权威原文再次检查。没有官网链接时，由导入人自行提供和核实原文来源。确认后勾选复核说明并启用；未复核资料不会参与回答。

错误会以红色提示固定显示在当前导入弹窗顶部，正文表单在其下方独立滚动；不会在几秒后自行消失。导入失败时表单内容保留，可修改后重试。“同名法规、版本和地区已存在”表示该版本已导入，不需要反复提交。

交叉引用即使出现在换行后的行首，也会根据引用词和前后文识别，保留在原条文中；预览会提示数量。疑似重复标题会给出行号和片段供核对，不会自动删除重复内容。明确标注的后附起草说明与法条分开处理，排除范围会显示在预览中。

系统保存导入后的正文、来源名称和正文SHA256，不保存上传文件的二进制副本。请自行保管原始PDF/DOCX等文件。校验值用于识别导入文本变化，不是来源真实性证明。

官网访问受限、乱码、扫描PDF、目录重复条号或读取不到法条时，可以切换到文件 / 粘贴方式。系统不会绕过访问限制，也不会自动确认法条完整、适用或最新；资料管理员须维护版本并定期复核。

演示摘录只有3条，用于熟悉操作。正式研究前请换为完整的适用法规和司法解释。不能因为系统能展示某条引用，就认定它已检索了所有相关规定。

## 导出和删除

在案件页点击“导出记录”，得到Markdown文件，包含问题、结论、完整引用及确认事实，可用文本编辑器、Markdown工具打开或复制到文档。

“删除案件”会删除该案件对话及确认事实。删除法条库中的法规版本不会修改历史答案中的引用快照，但新研究不再使用该版本。

## 哪些事情需要管理员

首次部署、模型下载、API Key申请、网络/HTTPS设置、备份恢复和法库更新计划。页面出现模型接口错误时，可向管理员提供错误提示和发生时间，不要发送密钥。


## 1.2.0 核心流程

复制问题后逐项作答也可保留为本案事实；右侧查看自动陈述。回答先列“基于现有资料的结论”，再列“推荐补充资料”；缺专项文件不会自动阻断其他有依据的部分分析，但现有资料确实无法支持时不会编造结论。推荐来自研究目录和模型判断，再对照法库检查；名称、条号及适用性仍需核对，并不表示模型直接检查了磁盘上的文件。缺案件信息才列在“还需确认”。原法规名称是文件名时，到查看/复核填写标准法规名称。完整操作见 HTML 教程与 [核心流程](CORE_RESEARCH.md)。
