# 升级到 LexCite 1.4.0

本版完成P0/P1及R6整改代码，不扩展P2/P3产品功能。验证范围与剩余发布门槛见[验证记录](VERIFICATION_1.4.0.md)；启动成功、合成模型与真实法律准确率是不同验收目标。

## 1. 先备份，保留部署身份

保存当前代码版本及部署配置，执行[部署手册的SQLite备份](DEPLOYMENT.md#8-备份与恢复)。备份包含案件、法库和解密服务密钥所需文件，须按案卷保管；`.env`另行安全备份。验证备份可在隔离空目录恢复后，再更新正式实例。

沿用原项目目录、Compose项目名与`lexcite_data`卷；Python部署沿用原`LEXCITE_DATA`。**不得删除数据卷、覆盖`.env`、清空法库或重新初始化工作空间。** 环境变量中的初始密码不会覆盖数据库现有密码。

## 2. 一起更新后端和静态资源

完整更新`app/`、`static/`、`scripts/`、Docker/Compose配置及文档，不能只复制`app.js`。后端、HTML、脚本和资源路径均为1.4.0；混用版本会明确阻止登录。

Docker部署在原项目目录运行：

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=30 lexcite
```

使用Ollama/重排组合时，继续使用原有的全部`-f`配置文件。不要执行`docker compose down -v`。

Python部署停止旧进程，按原虚拟环境安装`requirements.txt`，再运行：

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8080 --workers 1 --no-proxy-headers --forwarded-allow-ips=
```

只运行一个worker。首次启动自动增加筛选索引、法库修订号和触发器，保留业务数据；重启恢复将未完成任务标记为中断。升级前的研究记录仍保留当时的完整引用快照。

## 3. 重新核对服务和部署配置

- 新实例的初始化码在`data/setup-code.txt`，不在日志。Docker读取命令为`docker compose exec lexcite cat data/setup-code.txt`；已初始化实例不需要、也不会保留该文件。
- 检查`.env.example`新增的`LEXCITE_TRUST_PROXY=0`与`LEXCITE_LOCAL_RECOVERY=0`，手工合并到原`.env`，不要覆盖已有密钥。
- 可信HTTPS反代必须覆盖XFF为`$remote_addr`、隔离后端端口，并显式启用TRUST_PROXY、Secure cookie和HSTS；无反代时不要启用TRUST_PROXY。所有Uvicorn启动命令禁用其默认代理头解析。完整示例见[部署手册](DEPLOYMENT.md#7-https与内网访问)。
- 正确密码不受匿名失败次数触发的全员账号锁定；应用限流仍不能代替边缘连接/速率限制。本地恢复仅用于隔离宿主机的直接loopback连接，仍须正确密码，用完关闭。
- 存量服务配置现在重新校验。无效私网端点会显示错误、停止使用，但设置页仍可修复；文档化服务名及11434/8081回环端口有明确例外，停用的检索服务不校验闲置地址。
- 环境密钥同样绑定服务商与端点；分析密钥另绑定配置档。过去依赖“改变地址后自动复用环境密钥”的部署须重新配置。API中的`null`/省略表示同端点保留，显式`""`表示清除并禁用环境回退。

保存和测试分析、向量、重排、搜索服务，逐一确认当前配置；测试真实服务可能收费。设置不能在研究/索引任务占用模型槽时并发切换。

## 4. 复核旧法库，再补齐索引

本版修复BOM/零宽字符、Unicode换行、全角/混合数字、章节误删、折行引用、Markdown、多层DOCX及异常PDF。**不会自动重解析已保存条文。** 旧版中被吞掉、误分成虚假条文或漏读的内容，仅升级程序或重建向量无法修复。

先备份并对照权威原文检查条数、边界、章节、正文及SHA256。需要重导入时，先记录原版本元信息，再删除错误版本、用原始完整文本重新导入和人工复核；相同法规身份与文本的重复导入会复用既有版本，不能靠重复上传覆盖错误拆条。不要同时留下日期重叠的同名启用版本。

源文本快照和SHA256保持原提交文本，规范化只用于解析副本。对复杂附件仍须人工核查阅读顺序；扫描PDF不支持OCR。超预算的点名条文会显示明确警告，不截断原文；需要全部原文时使用“仅查法条”。

确认向量服务与指纹，再“建立 / 补齐向量索引”。旧向量仅在模型、维度、版本、正文及元信息匹配时复用；更换配置后补齐当前指纹索引。直接SQL修改法库会更新修订号并使检索缓存失效，但不能替代人工复核。

## 5. 升级后验收与回退

用隔离测试案件完成登录、导入预览/复核、查询、引用打开、停止/刷新恢复、确认事实与导出。断网或轮询失败后应保留问题并解除界面等待，“恢复查看”不得再次创建研究。

再在目标环境验收真实国产聊天/向量/重排、本地Ollama、真实重排权重、可信反代及法律人员标注的评测。尚未完成的门槛不能由合成夹具替代，详见[本版记录](VERIFICATION_1.4.0.md)。

回退时停止新实例，恢复升级前的代码、`.env`及完整备份到隔离空数据目录，确认后再替换正式数据。不要让旧版直接读升级后已修改的数据来代替备份恢复，不要覆盖运行中的SQLite。
