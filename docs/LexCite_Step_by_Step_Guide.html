01 / 所有路线共用

启动法据

本章只启动法据。模型会在后面的 API 或 Ollama 章节中接入。

1.1

安装并打开 Docker Desktop

macOS：打开 Docker 官方 Mac 安装页。点击电脑左上角苹果图标 →“关于本机”，根据芯片选择 Apple silicon 或 Intel 安装包。打开下载的安装包，将 Docker 放入“应用程序”，然后启动 Docker。

Windows：打开 Docker 官方 Windows 安装页，按页面要求选择安装包。运行安装程序；如果提示安装或启用 WSL 2，按官方引导完成，并在要求时重启电脑。重新打开 Docker Desktop。

Linux：由管理员按 Docker Engine 官方说明安装引擎及 Compose 插件，并让当前账户能够使用 Docker。后续命令与本教程一致。

等 Docker 引擎启动完成。只安装、没有打开 Docker，法据无法启动。厂商安装页的系统要求如有更新，以页面为准。

1.2

解压项目，进入正确的文件夹

解压 LexCite_1.3.0.zip。进入其中的 lexcite 文件夹，确认能看到 compose.yaml、Dockerfile、README.md 和 start.bat。

Windows 打开终端：在资源管理器打开这个文件夹，点击顶部地址栏，输入 powershell，按回车。新窗口通常已经位于该文件夹。输入以下命令确认：

Windows PowerShell
Get-Item .\compose.yaml

如果更习惯双击，直接双击 start.bat；它会启动服务并显示日志。后续需要其他命令时，再按上面的方式打开终端。

macOS 打开终端：打开“终端”应用，输入 cd 并留一个空格，再把 lexcite 文件夹拖入终端，按回车。拖入的路径由电脑自动填好。然后输入：

macOS 终端
ls compose.yaml

Linux：在 lexcite 文件夹打开终端，运行 ls compose.yaml 确认位置。

看到文件名才说明位置正确。若提示找不到文件，通常是进入了解压包外层目录，再进入下一层 lexcite 即可。

1.3

检查 Docker，再启动项目

所有系统：检查 Compose
docker compose version
所有系统：检查 Docker 引擎
docker info

前者应显示版本号，后者应有服务端信息且没有连接失败。然后执行：

终端命令
docker compose up -d --build

首次会下载基础镜像和 Python 依赖，请等命令结束。以后重启无需重复下载所有内容。命令执行失败时先查看最后几行错误，不要继续寻找初始化码。

查看运行状态
docker compose ps

列表中应出现 lexcite，状态为运行中；健康状态刚启动时可能显示 starting。如果反复重启，查看第 8 章的排错表。

1.4

打开应用

在浏览器地址栏输入或点击：

http://localhost:8080 打开法据 ↗

应看到“法据”及初始化/登录表单。请通过这个地址使用应用，不要双击项目里的 static/index.html。

D6

连接失败时，按这个顺序检查

你看到的现象怎么处理
HTTP 401：认证失败重新复制 API Key；确认使用 DeepSeek 官方密钥，未混入空格、引号或 Bearer；保存后再测试。
HTTP 402：余额不足到 DeepSeek 开放平台检查账户余额及计费状态。
HTTP 429：请求达到限流等待后再试，减少连续点击；检查账户限额。
HTTP 400 / 422：请求或参数问题核对地址、当前模型 ID 和官方 JSON 支持；仍失败时让管理员核查接口适配。
HTTP 500 / 503可能是服务端错误或繁忙；稍后重试，持续发生再联系服务商。
模型不存在 / 404确认未继续使用旧预设；从平台或官方模型列表复制精确 ID。地址不要重复追加接口路径。
保存后似乎还是旧配置检查是否先保存再测试；若页面提示环境变量覆盖，需要管理员核对部署中的 MODEL_* 设置。
连接通过，但提问没有分析确认选“研究 Agent”；检查法条是否已复核、日期地区是否匹配，以及生成或证据复核是否回退。

错误码依据：DeepSeek 官方错误码说明。模型兼容性和法据配置项结合本项目代码说明。

费用与资料去向：使用 DeepSeek 官方 API 时，问题、召回的用户历史、已确认事实及相关法条会由法据后台发送给 DeepSeek。密钥在法据服务器端保存。先用本教程的虚构练习案件完成验收，再按所在单位要求决定哪些正式资料可以使用该服务。

Ollama 默认只监听本机地址。法据在 Docker 中时，需要让容器能访问宿主机的 Ollama。下面设置监听地址和 32K 上下文；较长上下文会增加内存需求。

变量名变量值
OLLAMA_HOST0.0.0.0:11434
OLLAMA_CONTEXT_LENGTH32768

终端命令
sudo systemctl edit ollama.service

在编辑器中写入以下服务配置并保存：

服务配置内容，不是终端命令

4.1

  2. 法库为空时，点击 载入演示摘录。
  3. 弹窗会自动填入法规名称、版本、日期、官方链接和正文。
  4. 点击 预览条文拆分，应显示“共识别 3 条”。

  2. 逐条对照正文、条号、否定词和数字；确认这是明确标记为“仅 3 条”的演示摘录，并非完整民法典。

5.2

先不调用模型，只查原文

在问题输入框粘贴：

练习问题
对方逾期未支付合同价款，可以请求其支付吗？

将输入框下方的回答方式改为 仅查法条 · 原文检索，点击 开始研究 ↗。

应看到：相关法条卡片，例如第五百七十九条。此模式不调用聊天模型，适合先确认法库和检索是否工作。没有结果时，先查复核状态、研究日期和地区，不要急着换模型。

5.3

让模型分析，再检查引用

再次输入同一个问题，将回答方式切换为 研究 Agent · 分析与引用校验，点击“开始研究”。程序会检索、生成并复核，不会在检查前逐字展示未验证结论。

点击回答中的 [1] 或下方的法规卡片。弹窗中核对：

  • 法规名称、条号和版本是否正确；
  • 引文与完整条文是否一致，有没有遗漏限制条件或例外；
  • 生效/失效信息、复核时间和适用地区是否符合问题；
  • 点击“核对官方来源 ↗”，回到官方原文；
  • 结论是否确实得到法条支持，而不只是“引用看起来真实”。
回答状态怎么理解下一步
已核对引用已通过原文匹配和本次模型复核继续人工核对法律适用
部分结论只有一部分结论通过，或问题仍缺依据/事实查看“还需确认”，补资料再问
仅供原文核对使用原文模式，或模型生成/校验失败后回退先查运行模式，再展开检索与校验过程
依据不足没有找到可用于这次回答的已复核依据检查法库范围、日期、地区，或缩小问题
不用强求每个问题都给出确定结论。三条演示法条不足以回答诉讼时效、管辖、违约金计算等完整问题。需要的规范未导入时，补充法源比反复要求模型“直接回答”更有帮助。
06 / 日常操作

让法据记住案件事实

1.3.0 支持在同一消息中复制多个问题后分别作答，例如“是否登记？办了。共同生活多久？一年。”自动整理项会保留原话来源，刷新后仍在；它们不自动升级为手工确认事实。更正时写“更正：……”，未知事项明确写“未知”。

6.1

手工确认事实，避免把推测存进去

在刚才的练习案件右侧，点击 ＋ 添加确认事实。为这个虚构练习填入：

练习事实
【操作练习】合同约定买方应于2025年6月30日前支付货款。截至2025年7月1日，买方尚未付款。

点击 确认并保存，应看到事实卡片以及增加后的记忆数量。正式案件只保存已经核实的事实；不要把“模型认为已经构成某种责任”直接当作确认事实。

6.2

继续追问并核对记忆

在同一案件内继续问：

多轮练习问题
结合我保存的付款期限和未付款事实，现有法条能支持哪些请求？还需要核实哪些事实？

模型会收到本案确认事实、带来源原话的用户陈述摘要，以及有限的历史用户消息。右侧“已收到的信息”显示已提供、明确未知或存在矛盾，回答中的“本轮采用的用户信息”保留该次快照。完整对话仍会存档；历史模型回答和思考不会被当作事实或法源重新使用。复杂表述可能无法完整整理，关键内容请手工确认。

6.3

切换案件，导出记录

  1. 刷新网页或重新登录，从左侧“最近案件”打开原案件，检查对话和确认事实仍在。
  2. 新建另一个练习案件，右侧不应自动出现上一案的事实。
  3. 打开需要留存的案件，点击顶部 导出记录，下载 Markdown 文件，内含问题、回答及引用原文。
  4. 事实有误时点击对应卡片的“移除此事实”；这不会改写已经生成的历史回答。纠正后应重新研究。
记忆隔离是按案件分开的，不是人员权限隔离。项目 1.3.0 使用一个工作空间密码，同一工作空间的登录者都能访问其中案件。一个案件最多保存 30 条确认事实。
07 / 导入法条后完成

建立索引与日常维护

服务地址、模型和密钥已统一放入 国产 API 配置与 本地配置。完成三个服务的连接测试，并导入、复核法条后，在这里建立索引并检查实际检索状态。

默认选中“混合检索”不等于已经启用语义召回。

只有向量服务和索引可用时，语义召回才会参加检索；缺少法源仍需导入或联网补查。

7.1

保存、测试，再建立索引

  1. 点击“保存检索配置”。密钥输入框会清空并显示“已保存”，这是正常行为。
  2. 分别点击“测试已保存的向量服务”和“测试已保存的重排服务”。前者应报告实际向量维度；后者应报告有效分数数量。
  3. 导入并复核所需法规后，点击“建立 / 补齐向量索引”。在下面卡片查看“已索引、待处理、失败”数量；可刷新后回来查看，也可点击“停止索引”。
  4. 等待已索引数达到预期，待处理和失败均为0，再勾选自动索引并保存。后续新增或复核更名的法条会自动补齐。
  5. 出现失败时，卡片会显示具体原因。处理地址、权限、模型名称等问题后，再点击补齐；已完成条文不会重复处理。
7.2

确认这次研究真的用了语义检索

  1. 回到案件研究，重新提问。
  2. 展开答案下方“本次实际检索”，核对向量模型、重排模型、索引覆盖数、候选数和状态。
  3. “向量已使用＋重排已使用”才代表这两个环节实际成功。未配置、没有可用索引、部分覆盖、失败并降级均会单独标明。
  4. 官网临时条文不自动建立整部法规的向量索引；其关键词/重排路径与本地法库分别记录。候选相似不等于结论受到法律支持，继续点击引用核对完整条文。
升级后为什么要重建？改变模型怎么处理？

旧版向量设置会首次迁移到独立服务，但不会自动花费额度重建；检查配置后手动建立一次。旧向量缺少完整输入指纹，新版不会混用。更换模型、维度、地址、版本标记、查询指令、分片规则后会显示新模型待索引数量。不要删除案件或重新初始化。同名模型由服务商更新后，可修改“高级索引设置 → 模型版本标记”并重建。

如何比较改造前后的实际检索效果？

由部署管理员运行以下命令；它会调用已配置服务，可能产生费用，在临时数据库副本中处理法库，不复制正式案件：

固定法库的三组对照：关键词／混合／混合＋重排
docker compose exec lexcite python scripts/evaluate_retrieval.py --run-live --build-index --output /tmp/retrieval-evaluation.json
docker compose cp lexcite:/tmp/retrieval-evaluation.json ./retrieval-evaluation.json

报告分开列出“法源未收录”和“已有法源未召回”，未真正使用目标服务的运行不会冒充有效对照。内置10题只是起步验收集，需由法律人员扩展并确认参考条文。接口测试、合成向量测试和浏览器通过不代表已测得真实法律正确率。

每天如何打开、停止和重启？

API 路线或 B2：先打开 Docker Desktop，需要本地模型时再打开宿主机 Ollama；项目目录中执行：

恢复已经创建的法据容器
docker compose start

然后浏览器打开 http://localhost:8080。暂停法据：

终端命令
docker compose stop

B1：恢复/暂停法据和容器中的 Ollama：

终端命令
docker compose -f compose.yaml -f compose.ollama.yaml start
终端命令
docker compose -f compose.yaml -f compose.ollama.yaml stop

使用第3B章本地重排组合时，启动/停止命令也应加上 -f compose.reranker.yaml，使重排服务一同启停。普通停止和重启保留数据卷。不要把带 -v 的删除数据卷命令当成日常关闭方式；也不要在 Docker Desktop 中删除存有案件的卷。

如何备份案件、法库和配置？

在项目目录依次执行下列命令，生成第一份备份。下一次把 01 换成 02 等新编号；脚本拒绝覆盖已有备份。

终端命令
docker compose exec lexcite python scripts/backup.py --data /app/data --output /app/data/backup-01.zip
终端命令
docker compose cp lexcite:/app/data/backup-01.zip ./lexcite-backup-01.zip

项目文件夹中应出现 lexcite-backup-01.zip。将其保存到单位认可的备份位置。它包含案件、法库及解密模型密钥所需文件，应按案件资料保护。恢复需先停止服务，再按项目 docs/DEPLOYMENT.md 中的空目录恢复步骤操作。

法规更新、旧法和复核周期怎么处理？
  • 默认复核周期 180 天；超期会暂停参与回答。复核是重新检查官方版本，不是单纯点击一次续期。
  • 新版本作为新记录导入，按真实施行信息设置有效期；旧版本应填正确失效日。
  • 地区匹配为“全国 + 同名地区”，不会自动推导省市层级关系。
  • 历史答案保留生成时的引用快照；更新法规后，应针对当前研究日期重新提问。
08 / 有问题先查这里

按现象排错

提示 no configuration file provided / 找不到 compose.yaml

终端不在正确目录。进入真正含 compose.yaml 的 lexcite 文件夹，再执行命令；参考 1.2。

提示 cannot connect to Docker daemon / Docker 引擎未连接

打开 Docker Desktop 并等引擎启动。运行 docker info 确认；不要只检查 Docker 是否安装。

首次下载失败、镜像拉取失败或安装依赖失败

查看启动日志中的具体下载地址与错误。镜像、Python 依赖和 Ollama 权重是不同下载步骤；让管理员分别检查网络、代理或组织内镜像源。不要随意使用来源不明的镜像或把 API 密钥当作 Docker 登录密码。

网页 http://localhost:8080 打不开

运行 docker compose ps 和下面的日志命令。如果容器反复重启，先处理日志报错。若提示端口 8080 被占用，可由管理员改项目配置中的 LEXCITE_PORT，然后重建；浏览器也要换成对应端口。不要随意停止不认识的其他服务。

终端命令
docker compose logs --tail=100 lexcite
初始化码不正确、找不到码、没有初始化输入框

参考第 2 章：复制的是当前实例的随机码，不是整行日志；已初始化的实例只用工作空间密码。初始化后删除的码不能再用来登录。日志和截图中请遮住真实码及密码。

模型 HTTP 401 / 403：密钥或权限问题

核对是否选错厂商、Key 是否完整、账户是否允许 API 调用、百炼地域/业务空间是否一致。切换服务后重新填密钥，点击“保存设置”再测试。不要把密钥贴到公开群或截图中。

模型 HTTP 404 / 模型不存在

检查服务地址是否重复加了 /chat/completions；检查完整模型 ID 是否仍在控制台可用。DeepSeek 的项目旧预设 deepseek-chat 需要按第 3A 章更新。Ollama 用 ollama list 或容器内对应命令确认实际下载位置和模型名。

模型 HTTP 400 / 不支持 JSON 或参数

新版会显示脱敏后的厂商错误代码和说明，先按具体字段排查。在“模型与设置”将“输出格式”设为“自动兼容”，保存并测试；百炼开启/默认思考时自动使用提示词 JSON。若其他兼容端点也不支持 response_format，可选“提示词 JSON”。再检查思考模式、模型名称、地址和输出长度；参数错误不会被当作“依据不足”，也不会反复用相同参数重试。所有模式仍校验结构和引用。

模型 HTTP 429 / 额度不足 / 余额不足

到该厂商控制台检查额度、余额及限流提示。等待限流窗口恢复后重试；账户余额不足不一定都返回同一个 HTTP 状态码，以厂商信息为准。

Ollama 连接拒绝 / 超时 / host.docker.internal 不通

先确认是 B1、B2 还是 B3，按地址表填写。B2 确认 Ollama 重启后监听生效、宿主机防火墙允许 Docker 所需访问，再执行 B2.3 的模型列表检查。浏览器能打开 Ollama 本机端口，不等于法据容器也能访问。

本地模型很慢 / CPU 占用高 / 内存不足

B1 默认使用 CPU，32K 上下文还会增加内存。首次加载慢并不一定是程序卡死。先使用三条演示资料、短问题，关闭其他占内存软件；必要时提高单次超时、使用原生/GPU 路线，或切换云 API。不要把性能不足解释成需要更多反复重试。

连接成功，但回答只有法条，没有分析

确认回答方式选择“研究 Agent · 分析与引用校验”，服务类型不是“仅检索原文”。展开“查看检索与校验过程”；结构化输出失败、原文匹配失败或复核不通过时都会保守回退。补充事实/法源、缩小问题或换合适模型。

提示输出被截断 / 法条超出上下文预算

先缩短问题，整理确认事实；截断输出可以提高“模型最大输出长度”，但该项不增加输入上下文。Ollama 的上下文需在服务端配置。长条文被拒绝时可先用“仅查法条”查看完整原文，不要为了强行生成而截掉例外条款。

总是“依据不足” / 法库有资料但不被使用

逐项检查：已经导入？状态已复核？复核是否超期？研究基准日期是否落在有效区间？地区名称是否匹配？是否存在同名版本重叠？最后再看问题是否需要当前法库没有的司法解释或地方规范。

版本冲突 / 演示民法典与完整版一起存在

打开法条资料库核对名称、地区和有效区间。确认不再需要演示后删除演示版本；真实新旧版本应按实际日期维护。不要改名字骗过版本检查。

导入按钮灰色 / 条文没有拆开

先把必填信息填完整，再点击“预览条文拆分”。修改正文后要重新预览。条文应在新行以“第X条”开头；扫描件需先 OCR 并校对，复杂 PDF 或表格 DOCX 建议转成干净文本。

保存后密钥框变空 / 修改设置不生效

密钥不会回显，看“已保存密钥”提示。测试前要先保存；如果显示环境变量覆盖，管理员需检查 MODEL_PROVIDER、MODEL_BASE_URL、MODEL_NAME、MODEL_API_KEY。修改部署环境后需要重新创建容器使其生效。

更改 LEXCITE_ADMIN_PASSWORD 后还是旧密码

该变量只在首次初始化时使用，不会覆盖已有数据库密码。已初始化实例使用原工作空间密码；需要重置时交管理员处理，先备份，不要删数据卷。

向管理员求助时提供：操作步骤、服务类型、模型名称、服务地址、报错原文、法据日志最后 100 行。截图中遮住 API Key、初始化码、密码以及不应外传的案情。这样能判断是启动、连接、检索还是回答校验阶段出了问题。
