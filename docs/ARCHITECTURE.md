# 架构与减少幻觉的机制

## 组件

Python 3.12 + FastAPI + SQLite；同一服务提供静态网页与API。前端采用浏览器原生HTML/CSS/JS，日常使用不需要Node或构建工具。默认不依赖外部向量数据库、在线检索服务或闭源模型。

核心代码位于 `app/research_agent/`，入口 `answer()` 供同步 API 和后台任务共同调用。普通路径是直接检索完整法条、合并相关性/覆盖检查与法律分析、确定性引文校验、独立模型支持性复核。通常两次核心模型调用；失败时按类型局部修引用、改写失败结论或重试复核，只有明确需要新依据时才规划补充检索。证据没有实质变化不重写整份分析，同一证据下的重复失败提前停止。达到上限保留已通过的部分，不因推荐文件尚缺而重复完整研究。

缺少专项文件时按范围开关补查官方完整原文。临时证据明确标注未人工复核，与搜索摘要分开。模块职责、调用预算和耗时记录参见 [核心研究流程](CORE_RESEARCH.md)。

纯原文模式跳过全部LLM调用；模型接口不可用时也会保守回退。推理正文不采用逐token流式输出，避免校验之前就向用户展示假结论。

## 检索

1. 默认用jieba分词加中文双字切分计算BM25；精确条号兼容阿拉伯数字与中文数字。
2. 原研究主题、用户陈述、当前追问及所需法源名称用于直接检索；修正时才增加最多三条模型改写查询，去重后最多九条查询。
3. 独立配置 Embedding 服务，已有文档向量持久存SQLite。每次本地检索最多一次问题 embedding 批量调用；取得新官方原文或修正查询时可能再次检索。
4. 候选列表用RRF融合。同法条明确引用其他条号时，最多补充3条关联证据。
5. 默认14条主检索结果，明确条号命中和有限交叉引用可能额外加入；生成上下文限18000个法条字符，以完整条文为单位加入，不裁剪条款中段。
6. 检索分数不显示为“法律正确概率”。相似度阈值没有经过业务校准，召回范围必须实测。

整库BM25在应用进程中按请求计算，适合小型试用法库；并非百万级文书平台。大规模部署应采用专用搜索索引并保持现有条文身份和版本元数据。

## 法源与时效

`laws`表保存法规名称、版本、规范类型、地区、可选官方URL、正文来源方式（文件/粘贴/链接）、来源名称、生效日、失效日、人工复核时间和原文hash；`articles`表保存完整条文与所属法规版本。1.0.1启动时以增加列的方式迁移旧库，旧引用快照不改写。

- 新导入法规处于未复核状态，无法参与回答。
- 复核周期默认180天，可配置；超期不再纳入检索。这是人工维护机制，并非自动判断最新有效法。
- 有效区间为`[valid_from, valid_to)`，未录入失效日不代表系统已验证永久有效。
- 地区匹配为“全国 + 用户填写的同名地区”，没有省市行政层级自动继承。需要省、市两级时，应分别开展研究或扩展辖区层级表。
- 同名/同地区多版本区间重叠时排除这些版本，不自行判断哪一版优先。
- 日期过滤不等于适用法的完整判断；溯及力、司法解释施行规则等仍需相应法源与专业审查。
- 文件或粘贴方式的官网链接选填；未提供时在复核、引用和导出中明确标注。填写的URL仍限制为HTTPS的gov.cn及npc.gov.cn域名。域名校验和正文SHA256都不证明上传文本的真实性或完整性，由人工复核完成。
- 官网链接方式由服务端读取正文，不调用模型补全法条；网页未识别到条号、访问受限或格式不支持时返回错误，不写入法库。

条文拆分先识别候选标题，再依据条号后的引用词、款项、列举符号和前行引用语排除交叉引用；排除的是拆分边界，原文仍保留。真正重复的标题按统一数字条号判重，给出行号和片段。明确标记的后附起草说明在预览中提示排除范围；规则无法覆盖所有排版和表述，必须人工核对预览。

## 引用与支持性

模型仅输出结论、类别和证据ID/原文，不控制引用最终编号、法规名、URL或时间元数据。服务器从检索结果构建引用卡片。

确定性校验包括：ID属于本轮候选；引文去空白后至少8个字符且连续匹配原法条（仅忽略空白）；模型正文未生成外部链接或未检索的条号。再调用一次复核模型检查事实、条件、例外、数字与结论的支持关系。

复核可指定同一端点下的另一模型；留空时使用同一模型。第二次模型判断不是独立法律保证，相关错误可能重复发生。复核失败、格式异常或缺少任一检查结果时，该轮未通过内容不会展示；接口问题只重试复核，结论问题按反馈局部修正或补充检索。已通过结论在同一组证据下保留，复核修改项时另提供这些结论以检查一致性；证据内容、版本或适用元信息变化或取得新官方原文时，旧结论先失效，再重新分析和复核。每轮校验要求相同，重试不降低标准。达到轮数/时间上限后保留仍有效的已通过部分或原文。

历史答案保存引用快照，因此删除或更新法库后仍能看到“当时回答用了什么”；它不会自动变成当前仍正确的答案。

## 记忆

- 完整对话持久存档于案件名下。
- 每轮从本案用户消息重新整理带来源原话的陈述（最多70项、18,000字符），另召回最多12条完整用户消息（合计8,000字符）。长消息中的短陈述仍可提取；摘要未纳入的段数会提示。助手历史回答和思考不参与提取。语句筛选和同句匹配是保守启发式，不保证识别所有复杂语义。
- 陈述区分 stated / unknown / conflicting；更正可替代同主题旧陈述，冲突保留待核对，不自动确认。跟进“之前不是告诉你了吗”保留原研究主题。
- 追问先按规范化原话去重，再最多调用一次模型识别改写重复项；模型必须给出存在于用户消息/确认事实中的 source_id 与原话。明确未知不会变成肯定或否定；引用存在并不等于语义分类绝对正确。
- 已确认事实由用户手工添加/移除，最多30条；助手不得自动写入。
- 当前问题与已确认事实总计超过10000字符时要求用户整理，不截断事实。
- 模型历史回答不加入下一轮法源或事实上下文。
- 每个案件独立存储，但工作空间内使用相同登录密码的人员可以查看所有案件。这不是人员权限隔离。

## 安全与运行边界

单进程部署；同一时间最多一个研究/向量索引任务，防止小型本地模型被并发压满。浏览器认证采用8小时HttpOnly/SameSite=Strict会话，服务端存令牌hash；密码scrypt。模型密钥由服务器端Fernet加密保存，密钥文件与DB分开；两者被同时拿走时不能提供离线保护。案件正文没有字段级加密，应使用主机磁盘加密和受控备份。

前端输出转义、CSP禁止外部脚本、变更API检查自定义请求头和Origin、请求体22MB限制，文件20MB限制。无外部CDN、无广告/分析追踪。导入与复核的错误显示在原生dialog内部，聚焦错误并保留输入。导入弹窗使用固定提示区域与独立滚动表单，避免提示随正文滚出视野。HTML、API和静态资源禁止缓存，页面使用带版本号的资源路径；启动时校验页面/脚本/后端版本。

`/api/extract-url`仅允许官方HTTPS域名和443端口；不接受URL账号密码。每一跳校验域名和DNS公网地址，连接固定到已校验IP，TLS仍验证原主机名；最多3次跳转、正文下载8MB、文本200万字符、连接读取超时和总读取时间预算。该读取器不使用环境代理、不转发浏览器Cookie或模型密钥；内网地址、非官网跳转、压缩响应或无法解析页面会停止读取，用户可改用文件导入。固定民法典入口仍另有1260条完整性检查；通用链接读取没有法规总条数数据库，不保证整部法规已经读全。

上传资料和模型输出均按不可信数据处理。提示词隔离降低注入风险但不能保证消除注入；模型可输出限定的检索计划；服务器控制本地检索、联网和官网读取。模型不能改写公开检索词、服务端点、复核状态、配置或执行命令。

`audit`记录关键操作类型、时间和目标ID，`messages`记录检索/校验摘要。该日志不是防篡改司法审计，单一工作空间也不能识别每个办案人员。

## 任务与可观察性（1.1）

`research_jobs` 保存任务输入、状态、事件序列、结果消息 ID 与时间；`messages` 继续保存最终问题/答案及引用快照。创建任务返回 202，前端轮询进度，后台线程在页面关闭后继续研究。问题/答案和任务完成状态在同一 SQLite 事务提交，重复 request_id 不重复生成结果。任务可以请求取消；正在等待的网络调用返回或超时后检查取消，流式模型在读取事件时检查。服务重启将未完成任务标记为 interrupted，不自动重试产生新费用。必须单进程单 worker，线程锁不是分布式锁。

事件由程序生成，包含阶段、轮次、状态、时长和可核对摘要，不把被否决草稿作为结论；所选第三方模型实际返回的思考可单独展示保存，未返回则明确说明。模型产生的公开检索计划会显示在进度中，但不是法源或结论。研究默认最多三轮 / 360 秒，总计最多18次聊天请求，涵盖计划、覆盖、分析、复核及可选事实整理/元信息检查；网络操作和本地计算的检查点间可能略超总预算，取消也不是供应商侧强制终止。详情见 [Agent 与联网](AGENT_AND_SEARCH.md)。
