# 升级到 1.2.0：核心研究流程

1. 先停止正在运行的研究，备份现有数据库和 `secret.key`。沿用原项目目录、Compose 项目名及数据卷；不要执行 `docker compose down -v`。
2. 解压升级包，用新版应用代码、静态资源和文档覆盖旧项目。保留原 `.env`、本地 `data` 目录或原 Docker 数据卷。不要用空数据目录替换已有数据。
3. 在原项目目录运行 `docker compose up -d --build`；使用其他 Compose 文件的部署沿用原文件和启动参数。数据库会增加法规标准名称、文号和案件信息快照，不要求重新初始化。
4. 刷新网页，左下角与 `/healthz` 应显示 **1.2.0**。如果重新出现初始化页，先核对是否用了另一个项目名或数据卷，不要立即重新初始化。
5. 打开“法条资料库 → 查看 / 复核”。如果法规名称原来是 `mingfa` 等文件名，对照官方正文填写“标准法规名称”和文号，检查有效期后复核。不能根据条号猜测文件身份；原文件名保留，历史答案不改写。
6. 在案件提问框的“本次法源范围”选择“联网补齐官方法源”。内置目录中的文件直接读取官网；其他文件需要“模型与设置 → 联网搜索”配置博查或自建 SearXNG。默认仍是仅本地模式，管理员可改变默认值。
7. 在原案件中重新提问或继续补充事实。旧对话可重新整理；以前没有生成的正确结论不会被事后补写。重点检查右侧“已收到的信息”，再检查本轮引用。

## 这次行为变化

- 支持复制多个问题后分别回答，短回复可关联上轮问题；否定、未知、矛盾分别保留。明确的原话问答不会被模型改写成相反事实。
- 法规标准名称、版本、条号共同定位。其他法规的同条号不能替代所需文件。
- 增加法源相关性和覆盖检查。缺专项规定会单列文件名称，不再要求用户把“法律依据未在 evidence 提供”当成案件事实回答。
- 官网完整正文通过来源、元信息和条号检查后，可进入**本次临时证据**；明确标注未人工复核，不自动写入正式法库。检索摘要、读取失败页面仍不能作为法条。
- 回答按“对本问题的回答 / 规则与例外 / 结合本案事实 / 适用限制”组织。各项仍须有原文引用并通过支持性复核；未生成结论不会再显示“引用校验通过 0 项”。
- 无新增证据时停止重复检索；接口错误、事实缺口、法源缺口分别显示。

官网可能受访问限制，自动检查也不能保证排除所有后续修订与废止。当前交付未完成真实国产模型的法律效果验收，详见 `VERIFICATION.md`。需要验证你自己的模型时，可由管理员运行 `scripts/evaluate_core.py`。
