# 法据 LexCite

面向中文法律工作者的可自行部署研究工作台。完整前后端、数据库、中文界面、启动脚本、测试与说明均在此项目内。

**当前版本：1.3.2。** 新增独立向量与重排配置、后台增量索引、BM25＋向量＋精确条号混合召回、RRF与重排，以及每次研究的实际检索记录。1.3.1 增加服务器端 `.env` 密钥读取和有界并发批量索引；1.3.2 增加本地/API 双配置档。模型设置中先选“本地模型”或“云端 API”，服务商、地址、模型名随之切换；Embedding 与重排继续独立配置。升级步骤见 [UPGRADE_1.3.0.md](docs/UPGRADE_1.3.0.md)，检索配置见 [RETRIEVAL.md](docs/RETRIEVAL.md)，实测范围见 [验证记录](docs/VERIFICATION.md)。

## 已实现

- 本地中国开源模型：通过 Ollama 或兼容接口使用 Qwen 等模型；兼容本地 vLLM。
- 国产模型 API：界面预设通义千问、DeepSeek、硅基流动；模型名称可编辑。
- 中文工作界面：案件研究、法条资料库、模型设置、引用详情、研究记录导出；无需操作代码即可日常使用。
- 持久记忆：案件隔离、完整对话存档、人工确认事实；新一轮不会把历史模型回答作为法源或事实。
- 混合 RAG：BM25＋独立向量服务＋精确条号匹配、RRF融合、独立重排、完整法条回取、同法引用展开。配置和索引就绪后启用；未配置、失败或覆盖不全时显示实际降级状态。
- 后台索引：自动补齐、进度、停止、失败重试；模型/维度/版本/分片变化不混用旧向量，历史案件不重写。
- 可核对引用：逐项结论的法条编号、原文摘录、完整条文、版本、生效/失效日期、正文来源、人工复核时间、源文本 SHA256；官网链接未提供时明确标注。
- 研究 Agent：默认最多三轮规划、检索、分析与复核。引用失败后将具体反馈交回模型修正，达到上限后仅保留通过校验的内容；支持真实步骤进度、停止、刷新恢复。
- 可选联网：博查搜索 API 或自建 SearXNG，开启官方补查后，按缺失法规名称搜索或读取内置官网目录。完整原文通过自动检查后可用于本次条件分析，明确标注未人工复核；搜索摘要不作为法条依据。
- 模型思考：默认遵循供应商模型设置，可显式开启/关闭支持的模型；可展示并保存接口实际返回的 reasoning_content / reasoning，单独标为未校验；没有返回时如实说明。
- 数据管理：TXT/MD/PDF/DOCX 文件或粘贴正文导入（官网链接选填）；也可只填官网链接读取正文。保留拆条预览、人工复核、有效期与地区筛选、过期复核阻断、版本冲突阻断、备份恢复。

## 先启动，再在界面中配置

电脑须先安装并启动 Docker Desktop 或 Docker Engine + Compose。安装和服务器部署由管理员完成一次；律师/法官只需浏览器。

```bash
docker compose up -d --build
docker compose logs --tail=20 lexcite
```

打开 **http://localhost:8080**，复制日志中的一次性初始化码，设置至少12字符的工作空间密码。

Windows 可双击 `start.bat`；macOS/Linux 可运行 `bash start.sh`。如果已经通过 `.env` 配置 `LEXCITE_ADMIN_PASSWORD`，直接用该密码登录。

### 接入云端模型

在“模型与设置”中选择服务，输入模型名称和 API 密钥 → 保存设置 → 测试连接。无须修改源代码。示例名称需要与账户实际开通的模型一致。

### 接入本地 Ollama

已有 Ollama：拉取模型后，界面选择 Ollama，并填写服务地址与模型名称。应用和 Ollama 都直接在宿主机运行时，地址为 `http://127.0.0.1:11434/v1`；应用在 Docker、Ollama 在宿主机时，使用 `http://host.docker.internal:11434/v1`，并按部署手册配置 Ollama 的监听与防火墙。

也可以使用项目内的组合部署：

```bash
docker compose -f compose.yaml -f compose.ollama.yaml up -d --build
docker compose -f compose.yaml -f compose.ollama.yaml exec ollama ollama pull qwen3:8b
```

界面选 Ollama，地址填 `http://ollama:11434/v1`，模型填 `qwen3:8b`。此组合默认 CPU，速度取决于硬件；GPU 配置见部署手册。

## 配置语义检索与重排

“模型与设置”向下找到“语义检索与重排”。选择混合模式，分别配置两个服务：阿里百炼、硅基流动或本地服务。分析用DeepSeek时，也可单独选择硅基流动向量和重排，或Ollama向量配本地重排。服务不会继承聊天密钥。

首次可先关闭自动索引 → 保存 → 分别测试 → 点击“建立 / 补齐向量索引”。完成后开启自动索引。答案的“本次实际检索”应显示真正使用的向量/重排模型；填写hybrid不等于已启用语义召回。

项目根目录 `.env` 按分析模型的本地/API 两种运行方式，以及 Embedding、Reranker、Search 分组配置默认 provider、地址、模型和 API 密钥。模型设置先选“本地模型”或“云端 API”，再选具体服务；页面保存值优先于 `.env` 默认值。Docker Compose 与直接 Python 启动都会读取。密钥只由服务端使用，页面不会读取或回显明文；`.env` 已被 Git 忽略。索引后台最多并行4个请求、每次提交8个片段；中断后再次建立索引会从未完成的法条继续。

HTML教程的第3A章（国产API）和第3B章（本地）均按“分析模型 / Embedding / Rerank”三个标签配置；第7章统一完成索引与维护。宿主机Python法据连接重排容器的步骤也已包含。教程结构更新日期：2026-09-28。

本地三服务组合与字段逐项填法见 [升级说明](docs/UPGRADE_1.3.0.md) 及 [HTML手把手教程](docs/LexCite_Step_by_Step_Guide.html#advanced)。当前默认CPU重排尚未用真实权重测性能；检索配置成功与法律准确率是两个不同验收目标。

## 开启联网后，为什么仍可能缺法源？

“联网补齐官方法源”允许本次研究读取官网，不会自动创建搜索服务。千问、DeepSeek、硅基流动的聊天 API 密钥不能替代搜索配置。

- 内置目录中的刑法、民法典及两份婚姻家庭相关司法解释，直接读取已知官网地址，无需搜索密钥。目录仅是四份文件的地址清单，并非全国法规库。
- 目录外文件，或目录地址不可用后的搜索回退，需要到“模型与设置 → 联网搜索”配置博查或自建 SearXNG，保存并测试后重新研究。
- 新版会在“待补齐的法律依据”直接显示具体联网处理结果，并提供“配置联网搜索”入口。旧版本混合提示无法据此判断到底是否配置了搜索。
- 官方原文仍须通过名称、版本日期与主条号完整性检查。刑法整编文本另读修正案，不能把附则中的原法施行日当作修订版起始日。目录不覆盖的历史版本需人工导入。

## 首次使用顺序

1. 在“法条资料库”点击“导入法规”，选择“上传文件 / 粘贴正文”或“读取官网链接”，核对元信息并预览拆条结果。
2. 对照权威原文核对文本、版本、地区与有效期，再“确认复核并启用”。文件方式不强制填官网链接；引用会保留文件名并标注链接未提供。
3. 配置分析模型；再到“语义检索与重排”配置独立服务、保存并测试，建立索引。未配置仍可关键词检索，但界面会明确提示。
4. 新建案件，选择研究基准日期与地区，添加已确认事实。
5. 选择研究 Agent，提问并查看实时步骤；需要联网时选择“联网补齐官方法源”；目录外文件另需搜索服务。点击回答中的 `[1]` 等引用核对完整条文；需要时导出 Markdown 研究记录。

**法库默认为空。** `examples/civil_excerpt.json` 是3条真实法条的演示摘录，只用于验证流程，且默认未复核。它不能支撑全面法律咨询。导入完整民法典前请删除演示版本，否则同名版本有效期重叠会触发阻断。司法部在线读取入口会检查1260条完整性；当前开发环境访问该页面受重定向影响，未验证在线导入成功，手动导入路径可用。

## 设计取舍

采用“法条原文检索 + 逐项引用校验 + 模型复核”。本版实现有状态的研究循环，模型拟定与修订查询，服务器执行限定工具并管理预算、有效版本和输出校验。联网通过独立搜索服务完成，完整官方正文通过来源与元信息检查后可进入本次临时证据；长期法库仍须人工导入复核。保留完整法律原文，没有用 Skill 摘要替代条文。引用原文匹配和模型复核都不保证法律结论正确。

引文存在性校验可以确定性执行；“这条法律是否足以支持该结论”仍依赖模型与人工判断。**本项目不承诺零幻觉，也没有已测得的真实法律准确率。**

## 开发启动

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

另开终端运行：

```bash
python -m pytest -q
```

可选网页交互测试：安装Node.js 20或更高版本后运行`npm ci`，再运行`python scripts/test_ui.py`。测试会自动启动独立临时服务。具体测试结果和未测试事项见[验证记录](docs/VERIFICATION.md)。

## 使用范围

本版适合个人或同一可信团队的单工作空间试运行。当前使用一个工作空间密码，无多租户/案件访问权限分级；持久数据和备份含案件材料。正式跨机构部署前需要增加独立用户、案件权限、审计归属、法规更新责任及业务验收。应用默认仅绑定本机，完整细节见部署与验证文档。

本项目原创代码采用 MIT。未合并上游项目代码或模型权重；第三方依赖、模型及用户导入资料各自遵循其许可。
